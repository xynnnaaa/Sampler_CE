## 对比限制及收益

旧 runfile 的工作负载有 50,000 条 SQL；当前 config 指向 join_complexity_train.sql，共 49,640 条 SQL。按 SQL 多重集比较，新工作负载是旧工作负载删除 360 条后的子集，没有新增 SQL。template key 全部匹配，但 276 个 template 的查询数发生变化，960 个不变。因此两轮不是完全相同的 workload，不能把全部差异作为纯粹的缓存改动加速。

旧轮原始累计 27.9638 小时；新轮净累计 15.3413 小时，观测减少 45.14%（1.823 倍）。新轮原始累计 19.2910 小时，减少 31.01%。最长 worker 由 10,830.35 秒降至 7,461.06 秒，减少 31.11%，作为同步启动时的近似参考。

960 个查询数量不变的 template：旧累计 19.8652 小时，新净累计 10.7556 小时，减少 45.86%。随机种子及机器负载未固定，仍属于单轮观测，不替代完全一致工作负载的重复实验。

位图准备旧为 13.9887 小时；新 annotations.prepare 为 4.9442 小时，其中包含 3.9496 小时缓存等待。扣该等待后为 0.9946 小时，保留全部首次构建，观测缩短约 92.89%（约 14.06 倍）。

缓存块与 ID 文件大小 11,294,325,016 字节，即 10.519 GiB。首次缓存构建累计 2,031.1091 秒（33.85 分钟，跨构建者累计），数据库 FETCH 占约 27.28 分钟，批量打包写入约 5.75 分钟。只读映射累计长度不能视为实际磁盘读取量或同时驻留内存。
